# Deepal HU Translate

Перевод интерфейса головного устройства (ГУ) автомобиля Deepal / Changan S05
с китайского на русский через RRO-оверлеи (Runtime Resource Overlay).

**Нацелено на прошивку ГУ 3.1.2** — оверлеи собраны и проверены на этой сборке;
на других версиях прошивки не гарантировано.

## Что сделано

100 приложений ГУ с китайскими строками переведены (~17 800 строк), собраны
оверлеи — 100 динамических + 100 статических APK, автопроверка: 0 ошибок.
Актуальная статистика: `python3 generate_summary.py`.

## Установка (пользовательский путь)

### 1. Скачать архив

Последний релиз: [GitHub Releases](https://github.com/free4fan/deepal-HU-translate/releases)
— файл `deepal-HU-translate_v3.1.2-N.zip`. Номера: **`3.1.2` — версия прошивки ГУ**,
под которую собраны оверлеи; **`-N` — номер релиза** под эту прошивку
(следующий — `-14`, `-15`, …). Состав:

| Файл | Назначение |
|---|---|
| `manage.bat` (+ `collect_report.bat`) | менеджер **динамических** оверлеев, Windows |
| `deepl` / `deepl.exe` | тот же менеджер на Go (Linux/Windows), не требует adb в PATH |
| `targets.txt` | список приложений и групп установки |
| `apks_rro_min/` | APK динамических оверлеев |
| `apks_rro_static/` | APK статических оверлеев |
| `README.md` | этот файл — руководство пользователя (состав, установка, менеджеры) |

### 2. Подключить автомобиль и включить ADB

1. USB-кабель от автомобиля к ПК — правильный порт, не через USB-хаб.
2. Включить ADB на автомобиле через **инженерное меню ГУ** или программу
   **adbauth** на ПК (на самом ГУ «Для разработчиков» и кнопку «АВТОРИЗОВАТЬ»
   достать невозможно).
3. Проверка: `adb devices` показывает строку с `device`.

### 3. Запустить менеджер

Распаковать архив и запустить **`manage.bat`** (интерактивное меню) —
или без меню:

```bat
manage.bat               REM меню
manage.bat install 8     REM установить + включить TOP-8 (быстрый старт)
manage.bat install A     REM установить все группы
manage.bat report        REM собрать zip-логи для анализа
manage.bat reboot        REM перезагрузить автомобиль
```

То же самое через **`deepl.exe`**:

```bat
deepl.exe                REM меню (динамические)
deepl.exe dyn install 8  REM динамические, TOP-8
deepl.exe stat install A REM статические, все группы
deepl.exe report dynamic REM zip-логи
deepl.exe reboot
```

### Что менеджер делает сам

- **adb.** `manage.bat` ищет `adb` в PATH (нужны Android platform-tools).
  `deepl` ищет: env `DEEPL_ADB=путь` → PATH → `adb.exe` **рядом с бинарником**
  (просто положите в ту же папку). Выбранный путь печатается при старте:
  `[ADB] using: …`.
- **Язык.** Перед install/enable менеджеры выставляют локаль
  `ru-RU,en-US,zh-CN` (строка `[LOCALE]` в логе операций) — иначе при
  en/zh-локали автомобиля русский может не проявиться.
- **Корень.** Установка/включение запускаются от root; каждое действие пишется
  в `logs\ops_<режим>_<время>.log`.
- **Перезагрузка.** После install/uninstall перезагрузите ГУ (меню [8] /
  `reboot`) — статические оверлеи применяются только при старте, для
  динамических reboot гарантированно чистит кэш.

### Динамические и статические оверлеи

| Динамические (`apks_rro_min/`) | Статические (`apks_rro_static/`) |
|---|---|
| ставятся `adb install`, включаются/выключаются командой | лежат в `/vendor/overlay/` (root + remount), активны после перезагрузки |
| `manage.bat` / `deepl.exe dyn` | `manage_static.bat` (из git-репозитория, в архив не входит) / `deepl.exe stat` |
| ставится **91 из 100**: 9 AOSP-пакетов (NetworkStack, Providers, MTP и пр.) на этой прошивке `adb install` не принимает | 100 — туда же уходят и те 9 |

## Что в меню `manage.bat`

| Пункт | Действие |
|---|---|
| [1] Установить + включить | install + enable |
| [2] Включить / [3] Отключить / [4] Удалить | enable / disable / disable + uninstall |
| [5] Статус | список наших оверлеев: [x] включён / [ ] выключён |
| [6] Диагностика | локаль, оверлеи, dump по пакету |
| [7] Собрать логи | zip-отчёт: `logs\deepal_<dynamic\|static>_report_<время>.zip` |
| [8] Перезагрузить ГУ | `adb reboot` |
| [R] Проверить ADB заново | полная проверка (3 попытки + рестарт демона); вывод удерживается паузой «Нажмите любую клавишу…» |

Выбор цели: [1]–[4] группы (системные сервисы / основной интерфейс / важные
приложения / второстепенные), [8] TOP-8, [A] все, [C] 2+3, [auto] все APK из
каталога, [L] — список пакетов по номерам.

**Что отправлять при проблеме:** zip из пункта [7] — внутри сначала читать
`summary.txt`, он сам отвечает «есть ли проблемы» (не установлены / выключены /
FATAL / ANR).

## Если автомобиль не подключается

| Сообщение менеджера | Значение | Что делать |
|---|---|---|
| «Устройство не найдено» | автомобиль не виден adb | проверить кабель и порт; убедиться, что ADB включён (инженерное меню ГУ или adbauth) |
| «Устройство НЕ АВТОРИЗОВАНО» | ADB включён, но **публичный ключ adb этого ПК не добавлен на автомобиль** | на ПК запустить **adbauth** и добавить публичный ключ (`adbkey.pub` этого ПК) на автомобиль |

После исправления нажмите **[R]** в меню.

## Для разработчиков: пересобрать оверлеи с нуля

```bash
./create_app_pipeline.sh   # или по шагам — см. WORKFLOW.md
```

По шагам: декомпиляция → извлечение строк (`extract_cjk.py` — **обнуляет ru**,
гонять только для новых приложений) → перевод/улучшение
(`improve_translations.py`, LLM/Ollama) → `validate.py` → генерация
(`generate_overlays*.py`) + сборка (`create_rro_*.py`) → `validate.py`.
Зависимости: Java 21+, Python 3.12+, Go 1.22+, aapt2/apksigner (Android SDK),
`platform.jks`, Ollama для перевода. Подробности — **WORKFLOW.md**.

# shot (logshot) — снимок logcat ГУ + охота за фразой

Инструмент для фраз, **которых нет в APK** (проверено сканом: не в
`res/`/`resources.arsc`/`assets`/`dex`/`.so», UTF-8 и UTF-16) — они
приходят runtime: шина автомобиля (FDBus/ADAS), TBOX, scene.db,
TTS/нав-движок. Пример: `请检查四周情况,注意安全!` (видна в Camera) и
`即将执行主驾离车提醒` (сценарии).

## Что делает

Снимает живой logcat (буферы `main,system,crash` + наш host-штамп на
каждую строку) за заданное время, затем:

1. находит во всём снимке все вхождения каждой фразы (`-q`);
2. **сканирует ВСЕ китайские фрагменты** (`-cjk`) — известные заранее
   не нужны: токены агрегируются, сортируются по частоте;
3. парсит строки (`threadtime`): pid/tid/level/tag;
4. **атрибутирует pid → приложение**: `tr '\0' ' ' < /proc/<pid>/cmdline`
   (имя процесса), fallback — `pm map <pid>` (android-пакеты по uid);
5. писет 3 файла в `logs/logshot/`:
   - `shot_<ts>.log` — весь снимок;
   - `shot_<ts>.meta.txt` — окружение (locale, uid, device, pids камеры/сцен);
   - `shot_<ts>.hits.txt` — отчёт: хиты `-q` (контекст ±3 строки,
     совпадение `>>`) + CJK-fragment-отчёт + PID-карты.

### Режим `-cjk`: охота за всем китайским

Неизвестные заранее фразы — главная боль (их ещё нет в прошивке). `-cjk`
сканирует каждый снимок и выдаёт **все уникальные CJK-фрагменты** с
частотой, доминирующим pid-издателем, tag и образцом строки. Tокен —
непрерывный-run CJK-идеограмм (Ext A/B + Compat + Extended B/C/D);
латиница, цифры и CJK-пунктуация (`，。！`) — разделители. Т.е. одна
строка `请检查四周情况,注意安全!` → два токена: `请检查四周情况` и
`注意安全`. Разбиение по **сл**овам НЕ делается (нет сегментатора) —
токен может быть фрагментом большего смысла; читаемый смысл виден в
`ex:` (образец строки).

## Использование (Windows, рядом с ГУ)

```bat
shot.exe -q "请检查四周情况" -d 120            :: снять 120 с, охотиться
shot.exe -q "主驾离车提醒" -q "即将执行" -d 180  :: несколько фраз
shot.exe -cjk -d 180                           :: ВСЕ китайские фрагменты
shot.exe -q "фраза" -cjk -d 180                :: и фразы, и всё CJK
shot.exe -d -1 -q "..."                        :: снять до Ctrl+C
shot.exe -offline shot_20261002_213512.log -q "..."  :: охота по старому снимку
shot.exe -offline shot_20261002_213512.log -cjk     :: весь CJK из старого снимка
```

Рабочий процесс: запустить → показать сценарий на ГУ (дождаться, пока
фраза появилась и пропала; при `-cjk` просто «погулять» по меню) →
остановить (таймер/Ctrl+C) → читать `hits.txt`. Атрибуция pid — по
pid'ам из хитов (или CJK-издателем), cap 80 shell-вызовов.

## Сборка

```sh
logshot/build.sh          # gofmt + vet + тесты + ./shot (linux) + ./shot.exe (win)
logshot/build.sh --no-test
```

Модуль `logshot/` — отдельный Go-модуль (есть свой `go.mod`), не зависит
от `go/` (deepl). Бинарники — в корне проекта (`shot`, `shot.exe`).

## Структура

```
logshot/
├── go.mod
├── build.sh
├── cmd/logshot/main.go            # CLI: флаги, оффлайн/онлайн, glue
└── internal/
    ├── adb/      — adb (devices, shell, exec, live-Stream, подмены)
    ├── hunt/     — hunt.go: парс threadtime, Search(фразы), AttrPID
    │               cjk.go:  CollectCJK (всё CJK), CJKReport, sort
    └── shot/     — живой снимок: ring+file, meta, LoadFromFile
```

Тесты: `go test ./...` (все моки, adb не нужен).
